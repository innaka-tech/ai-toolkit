# Workflow specification

## 1. Repository layout

```
AGENTS.md                         instructions for every agent (§2)
CLAUDE.md, GEMINI.md              optional pointers to AGENTS.md, generated by adapters
aitk.toml                         project configuration (schemas/config.schema.json)
ai-state.json                     project state, schema_version 2 (schemas/state.schema.json)
docs/ai/
  project-context.md              purpose, stack, constraints; SHOULD stay ≤ 60 lines
  goals.md                        human-readable goals (structured copy in ai-state.json)
  application-map.md              optional; verified surfaces of the application
  tasks/<id>-<slug>.md            one file per task (§4)
  handoff/<YYYYMMDDTHHMMSSZ>-<id>.md   one file per session handoff (§6)
  handoff.md                      generated index of the 10 latest handoffs; MUST NOT be hand-edited
  current-task.md, knowledge.md   generated v1-compatible indexes (open tasks, knowledge topics) for agents
  decisions.md                    that still follow v1 instructions; MUST NOT be hand-edited
  knowledge/<topic>.md            curated knowledge (§8)
  knowledge/_inbox.md             new entries awaiting compaction
  knowledge/_archive/<YYYY>-Q<n>.md
  next-tasks.md                   generated suggestions
  _legacy/                        files preserved verbatim by migration
docs/adr/<NNNN>-<slug>.md         decisions in MADR 4 format
```

Rules:

- Committed files MUST NOT contain absolute paths, user names, or host names produced by aitk.
- Any other file under `docs/ai/` is user content. aitk MUST NOT modify it.
- Writes MUST be atomic (temporary file in the same directory, fsync, rename) and serialized by `$(git rev-parse --git-common-dir)/aitk/lock`.
- Per-worktree session state is stored in `$(git rev-parse --git-dir)/aitk/session.json` (schemas/session.schema.json) and is never committed.

## 2. AGENTS.md

aitk owns exactly one block, delimited by markers. Everything outside the markers belongs to the project.

```markdown
<!-- aitk:begin v=2 -->
## Working in this repository (aitk)

1. Run `aitk brief` and read its output. Do not read other files under docs/ai/ unless the brief points to them.
2. Run `aitk task start <id>` to continue a task, or `aitk task new "<title>"` to create one.
3. Do the work. Run `aitk check` until it passes.
4. Run `aitk close --summary "<what changed>" --knowledge "<lasting finding, or none>"`.
5. If unsure, blocked, the change is risky, or the check fails twice: stop and ask the user.

If `aitk` is not installed, read docs/ai/project-context.md and the newest file in docs/ai/handoff/.
<!-- aitk:end -->
```

- The block MUST stay ≤ 25 lines. It MUST NOT depend on MCP; every step is a shell command.
- `aitk init` and `aitk adapters sync` create or update the block idempotently. A changed block is reported by `aitk doctor`.
- The whole file SHOULD stay ≤ 120 lines; `aitk doctor` warns above that.

## 3. Agent protocol

| Step | Command | Writes |
|---|---|---|
| Orient | `aitk brief` | nothing |
| Select | `aitk task start <id>` / `aitk task new "<title>"` | session.json; task status → `in_progress` |
| Verify | `aitk check` | task `evidence.check` |
| Finish | `aitk close --summary … --knowledge …` | task, handoff file, knowledge inbox, handoff index |
| Hand over | `aitk switch <tool>` | handoff file (`outcome: switched`), brief for the next tool |

Agents MAY skip `task start` under the `lite` profile; `close` then creates an implicit task titled from `--summary`, using the worktree's latest check (`session.last_check`) as evidence.

## 4. Tasks

A task file is YAML frontmatter (schemas/task.schema.json) followed by Markdown sections:

```markdown
---
id: T-k3m9
title: Show invoice detail
status: in_progress
profile: standard
created: 2026-10-09T08:30:00Z
updated: 2026-10-09T09:10:00Z
---

## Objective
One paragraph.

## Acceptance criteria
- [ ] Given an issued invoice, when the user opens it, then line items and totals are shown.

## Risk
(Required for strict. Fields: Impact, Security (STRIDE), Rollback, Validation.)

## Notes
Free text.

## Evidence
(Generated by close.)
```

Status lifecycle (mirrors the v1 development standard):

```
todo → in_progress → implemented → in_review → done
            ↘ blocked ↗          (cancelled from any state)
```

- `aitk close` moves a task to the furthest status its evidence supports (§5).
- `in_review` → `done` requires review passes (§5, strict) or, for other profiles, a passing check.

## 5. Risk profiles and Definition of Done

The profile is computed from the diff between the merge base with `default_branch` and the working tree. A task's stored `profile` only takes precedence when it is pinned (`profile_pinned: true`, set by `--profile`):

| Profile | Condition |
|---|---|
| `strict` | Any changed path matches `risk.sensitive_paths`, or the task is pinned strict |
| `lite` | ≤ `risk.lite_max_files` files and ≤ `risk.lite_max_lines` changed lines, and not strict |
| `standard` | Otherwise |

`aitk close` MUST reject (exit 3, `E_DOD_*`) unless every rule of the profile holds:

| Rule | lite | standard | strict |
|---|---|---|---|
| `--summary` non-empty | ✔ | ✔ | ✔ |
| `--knowledge` given (`none` allowed) | ✔ | ✔ | ✔ |
| `check.cmd` configured → latest check passed on the current tree | ✔ | ✔ | ✔ |
| Every acceptance criterion written on the task is checked | ✔ | ✔ | ✔ |
| At least one acceptance criterion exists | | ✔ | ✔ |
| Risk section filled (no placeholder text) | | | ✔ |
| ≥ 2 review passes, last pass 0 findings, ≥ 1 pass by a different tool or session than the implementer | | | ✔ for `done`; otherwise status stays `in_review` |

"Latest check passed on the current tree" means `evidence.check.exit_code == 0` and it was recorded after the last modification of any tracked file.

## 6. Handoffs

`close` and `switch` write `docs/ai/handoff/<UTC>-<task>.md`: frontmatter (schemas/handoff.schema.json) plus a body containing the summary and the next steps. `docs/ai/handoff.md` is regenerated as an index of the 10 newest handoffs.

## 7. Brief

`aitk brief [--budget N] [--json]` outputs, in this order:

1. Project: name and the first 3 lines of `project-context.md`.
2. Task: the session's active task, or the most recently updated `in_progress` task, or a list of up to 5 open tasks. Includes status, profile, unchecked acceptance criteria, and next steps. When the project has no tasks but `_legacy/current-task.md` exists (free-form v1), the first 40 lines of it are shown instead, labeled as legacy.
3. Last handoff: the newest handoff for that task (or for the project), summary and `next`.
4. Knowledge: up to 15 entries ranked by (a) pinned, (b) topic or tag overlap with the task and with paths changed on the current branch, (c) recency. Plugins with the `brief.sections` hook MAY add entries here.
5. Rules: the profile's Definition of Done (§5) as ≤ 10 lines.
6. Next commands: 3–5 commands that fit the current state.

Budget: tokens are estimated as `ceil(utf8_bytes / 4)`. When over budget, aitk removes knowledge entries from the lowest rank first, then shortens the handoff body, then truncates notes. Sections 1, 2, 5, and 6 are never removed. Output MUST be deterministic for identical repository state.

## 8. Knowledge

On disk, an entry is one Markdown bullet with trailing metadata:

```markdown
- Invoice totals must use decimal strings end to end; float rounding broke US-19. <!-- aitk:k date=2026-10-09 task=T-k3m9 tags=money,invoice -->
```

- Grammar: `- <text> <!-- aitk:k date=<YYYY-MM-DD>[ task=<id>][ tags=<slug>(,<slug>)*][ pin] -->`. Entries without metadata (hand-written) are valid; their date is the file's last commit date.
- Entries SHOULD be one or two sentences; `aitk doctor` warns above 500 characters. The hard limit is 4000 characters so that migrated v1 entries are kept intact.
- `close` appends to `_inbox.md`. `aitk knowledge compact` runs automatically when the inbox exceeds `knowledge.inbox_limit`:
  1. Exact and normalized-duplicate entries are merged (whitespace, case, and punctuation insensitive).
  2. Each entry moves to `<topic>.md`, where the topic is the first tag, else derived from the task's tags, else `general`.
  3. Unpinned entries older than `knowledge.archive_after_days` move to `_archive/<YYYY>-Q<n>.md`.
  Compaction MUST NOT delete text. Rewording by a model is out of scope for the core; a plugin may propose it as a diff.
- `aitk knowledge search <query>` ranks by term overlap and recency, then merges `knowledge.search` plugin results.
